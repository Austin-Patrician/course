## 0. 这一讲原先缺什么(用户反馈)

1. **五个工具看起来一样** —— 十个工具页共用同一套骨架(左身份栏 + 右白卡示意图),
   示意图又都由同样的「窗口矩形 + 圆角胶囊」拼成,肉眼分不出。
2. **没有讲"为什么是现在"** —— 观众不知道 2026 年这批工具是怎么冒出来的。
3. **没有讲"命中什么需求"** —— 只有功能罗列,没有"它替谁解决了什么"。
4. **没有"怎么选"** —— 结尾只说"写代码的选前三个",不是真正的决策路径。

## 2. Codex(OpenAI)

**它是什么**:OpenAI 自己的编程 agent。**一个内核,四套壳**。
同一个 agent 内核 + 同一份 `AGENTS.md` + 同一份订阅额度,外面套四种入口。

| 形态 | 现状 |
|---|---|
| 终端 CLI | 开源,2025-04 发布,持续保留,适合脚本/CI |
| 桌面 App | 2026-02 推出;**2026-07-09 并入新的 ChatGPT 桌面端**,成为「Codex 模式」 |
| 云端 | 浏览器里跑长任务,可并行 |
| IDE 插件 | VS Code 系,保留 |

**为什么现在火了**(用户要的"流行原因"):
- 2026-01 周活约 **60 万** → 2026-03 破 200 万 → 04-21 破 400 万 → 06-02 破 **500 万**(OpenAI 官方口径,经 36氪/智东西 引述)。
- 转折点是 2026-02:同一天发 **Codex 桌面应用** + **GPT-5.3 Codex 模型**;后者在 Terminal Bench 上对 Claude Opus 4.6 领先 10% 以上。
- 2026-07-09 OpenAI 把 ChatGPT、Codex、Work 三种模式收进**同一个桌面客户端**;独立 Codex App 下线。
- 早期为什么不行:Windows 支持不到位、编辑文件/联网搜索不如 Claude Code 顺手、模型编程口碑被 Claude 压着。
  → 2026-03 时 Claude Code 周活 420 万,Codex 不到 100 万(不到 1/4)。**它是翻盘上来的,不是一开始就强。**

**命中什么**:**"我已经在付 ChatGPT 订阅了,不想再装一个新东西。"**
2026-06 官方数据:约 **20% 用户不是开发者**,且非开发者增速是开发者的 **3 倍以上**。
Codex 桌面团队负责人 Andrew Ambrosino:市场、财务、法务团队在自发使用这个"为工程师设计的工具"。
OpenAI 的判断原话:**"非开发者才是真正的故事。"**

**它的特点(区别于其他四个)**:
- 能挂进 Slack / Notion / Google Apps 里同时跑多个 Agent(2026-02 更新,100+ 新插件)
- Automations:设一个心跳任务,它自己定时扫消息、排优先级、出晨报
- 跨应用操作能力最宽

**代价/注意**:
- 2026-04 起从"按消息计费"改成 **token 点数滚动窗口计费**,成本变得更不可预测;社区反馈"月烧 200 刀"。
- 开发者心智份额并不领先:VS Code 扩展评分 3.4/5(Claude Code 4.0/5);JetBrains 调查使用率 3%(Claude Code 18%)。
  → **用它的人多,但"爱它"的人少。**

**数字上屏幕**:**60 万 → 500 万**(周活,2026 年 1 月 → 6 月)

## 3. Claude Code(Anthropic)

**它是什么**:Anthropic 的编程 agent,**终端原生**。Anthropic 是刻意选终端的:
理由是对文件访问有最大控制权和最细的权限提示。

**为什么它是"终端里最出名的那个"**:
- 2025-05 发布,8 个月内超过 GitHub Copilot 和 Cursor,成为**最受喜爱**的 AI 编程工具。
- The Pragmatic Engineer 2026-01/02 调查(906 人):**46% 选它"最喜爱"**,Cursor 19%,Copilot 9%。
- JetBrains 开发者生态调查(2026-05~07):**39% 专业开发者在工作中使用**。
- Menlo Ventures:占企业 AI 编程市场 **54%** 份额。
- Anthropic 官方 2026-02-12:周活自 1 月 1 日**翻倍**,run-rate 收入超 **$2.5B**;2026-05 周活 **200 万+**。
- 第三方估算:全球公开 GitHub 提交中约 **4%** 由它生成或参与;企业贡献其**超过一半**收入。
- 2026-07 Anthropic 披露:为 Claude 5 代模型调优,**删掉了 80% 以上的系统提示词**,编程评测成绩没掉。
  负责人 Boris Cherny 认为"让模型在执行中验证自己的工作"是当前最被低估的能力。

**命中什么**:**"这活要动几十个文件,聊天框靠不住。"**
它卖的不是"写代码快",是**敢把大改造交出去**。

**它的特点**:
- 仓库级改造(一次动几十个文件)
- 改完自己跑测试,失败继续改
- 同一个任务里能给不同子 agent 指定不同模型
- 生态深:Skills / hooks / SDK

**代价/注意**:
- 要 Claude 订阅或 API 额度,**没有独立免费档**;Opus 5.5 约 $4/$20 每百万 token。
- 2026 Q1 Anthropic 公开承认需求超出规划 **8 倍**,导致可靠性下降。
- 国内访问不稳定,大厂内部曾出现"要求卸载"的内部通知(微软 2026-06)。

**补充**:Anthropic 给办公室白领的对应产品是 **Claude Cowork**(2026-01 推出),
"用与 Claude Code 相同的 agent 架构,但不需要终端",面向文档/表格/研究。
→ 这正好是 WorkBuddy 的海外同构体。**课件里值得点一句**(说明"办公 Agent"是全场共识,不是腾讯独创)。

**数字上屏幕**:**46%**(开发者调研里选它"最喜爱"的比例)

## 4. Trae(字节跳动)

**它是什么**:国内第一个 **AI 原生 IDE**。不是终端工具,不是插件,是一个完整的编辑器。
TRAE = **T**he **R**eal **A**I **E**ngineer。

**沿革(这条对"它为什么是现在这样"很关键)**:
- 2024 年:豆包 MarsCode
- 2025-01 国际版 / 2025-03 国内版上线
- 2025-07 SOLO 模式 Beta;2025-11 SOLO 正式版(定位 "The Responsive Coding Agent")
- 2026-03-31 SOLO 独立端(PC + Web),推出 Code 与 MTC(More Than Coding)双模式
- 2026-05 SOLO 移动端上线,手机/电脑/网页三端互联,共享同一 Agent 与文件系统
- 2026-06 SOLO 更名为 **TRAE Work**(面向泛工作场景)
- **2026-08-24 TRAE、扣子(Coze)团队整体并入豆包体系**:TRAE Work 归入「豆包工作」,
  **TRAE IDE 与 CLI 作为豆包品牌下的编程产品线继续发展**。2026-08-25 字节发布「豆包工作」。

**数据**:
- 截至 2025-06 全球注册用户超 600 万,月活突破 160 万,覆盖近 200 个国家/地区
- 累计用户突破 **1200 万**(2026 年口径)
- 2026 年:**以 41.2% 份额居中国 AI 编程市场第一**(《中国企业家》,经 36氪 引述)
- 字节内部超 **80%** 工程师在用 TRAE
- 个人版**永久免费**

**命中什么**:**"我不想学终端。"**
给的是"看得见"的开发环境:左边文件树、中间代码、右边 AI 对话,改动有 DiffView 看得见。

**它的特点**:
- 从零搭项目:一句话描述需求,它把文件、代码、页面全搭出来
- 三种放手程度:只聊天 / 帮你搭 / 完全交给它
- 中文优先,支持语音交互(口语自动清洗 + 结构化转录)
- 上下文压缩(解决长上下文失焦,也省钱)
- 用国产模型(豆包 Seed 系列 + DeepSeek + Kimi),国内直连

**代价/注意**:
- 闭源,定制性有限
- 2026-08 起团队并入豆包体系,品牌与产品线在收拢 —— 讲的时候要说清"IDE 还在,只是归到豆包品牌下"
- 企业版定价较高

**数字上屏幕**:**41.2%**(中国 AI 编程市场份额,第一)

## 5. WorkBuddy(腾讯)★ 用户点名要的

**它是什么**:腾讯云的**桌面办公 Agent**,官方定位"全场景职场 AI 智能体桌面工作台"。
**不是编程工具。** 目标用户是 HR、运营、行政、销售、市场。

**出身(很反直觉,是很好的口播素材)**:
- 来自腾讯云一支十余人的 **AI 代码助手团队**(CodeBuddy 团队)。
- 2026-01 中旬一个周末,产品负责人汪晟杰和一位运营同事**熬了两个通宵**做出 0.01 版:
  极简对话界面 + 预装精选 Skill,打开就能用。
- 公测前腾讯内部已有 **2000+ 非技术岗员工**(HR、行政、运营、销售)每天在用。
- 2026-02-06 启动内测;上线三个月团队从 10 人扩到 100 多人,发了 **43 个版本**。
- 被称为「**腾讯版小龙虾**」,完全兼容 OpenClaw 技能生态。

**为什么火(用户点名要的"当今流行的原因")** —— 四条,按重要性排:

1. **零门槛,下载就能用。**
   Codex 和 Claude Code 要在本地跑起来,得先搞定网络、账号、权限,普通人还没开始干活就卡住了。
   WorkBuddy 直接砍掉这一层:下载安装 → 微信扫码 → 打开就用。
   在 B 端环境里,这意味着 IT 不用额外配置、不用安全审计,员工自己就能上手。
   → **这是 C 端思维做 B 端工具的打法,也是它渗透企业环境的核心原因。**

2. **不用学指令,有现成技能。**
   内置 20+ 技能包(数据处理、竞品调研、内容创作、舆情分析),每个技能背后是一套预设工作流。
   技能市场 SkillHub 已收录 **7 万余个技能**,两个月下载量 **3000 万次**。
   产品负责人的原话:**"用户不用懂什么是 Agent、什么是 tool,他只需要知道自己要什么。"**

3. **人在外面也能干。**
   绑定微信/企业微信后,手机发一句话,家里电脑自己开工,干完把结果发回微信。
   支持 微信 / 企业微信 / QQ / 飞书 / 钉钉。
   → 这是 Anthropic 和 OpenAI 在国内复制不了的东西:**IM 基础设施就是入口。**

4. **多模型 + 本地沙箱。**
   接入腾讯混元、DeepSeek、GLM、Kimi、MiniMax 五大模型,按任务智能匹配。
   文件默认在本地处理,只能访问用户授权的文件夹,敏感目录拦截,高风险操作二次确认。

**数据(强)**:
| 指标 | 数值 | 出处 |
|---|---|---|
| 桌面端月访问量(2026-06) | **2097 万次**,行业第一,**超过第二、三名之和** | 易观,经 36氪 引述 |
| 上线 90 天月访问 | 885 万,环比增速 **831%**,是行业第二名的 2.6 倍 | 新浪财经 2026-07-23 |
| 活跃用户留存率 | **>60%** | 腾讯 2026 Q1 财报 |
| 付费用户留存率 | **>80%** | 同上 |
| 官方定性 | 马化腾在 2026 Q1 财报电话会上三次点名,称其为「**中国使用最广的效率智能体服务**」;按日活跃账户数计中国最受欢迎的 AI 效率智能体 | 腾讯 Q1 财报 / 新浪财经 |
| 内部地位 | 马化腾几乎从不缺席 WorkBuddy 产品会,内部按「**超级项目**」推进;被认为是继 QQ、微信之后有潜力成为第三款现象级产品的业务 | 36氪 |

**代价/注意(必须讲,否则不诚实)**:
- **商业模式未经验证**。公测赠送 5000 Credits 吸引大批用户,人均 token 消耗三个月增长 10 倍,
  但免费额度用完后有多少人愿意持续付费仍是未知数。花旗研报:"最终命运尚待观察"。
- 透明度低:出错只能重发,难以调试;不适合超出场景列表的长尾任务。
- 敏感数据经由 IM 传输有隐私边界问题。
- **腾讯有四款名字很像的产品**:WorkBuddy(办公)、CodeBuddy(研发)、QClaw(微信遥控)、Marvis。
  原课件只写了两个,**要改成四个**。

**数字上屏幕**:**2097 万**(2026 年 6 月桌面端月访问量,行业第一)

## 6. DeepSeek Harness(DeepSeek)

**它是什么**:DeepSeek 开源的 **Agent Harness(运行环境)**。
一句话:**连界面在内,每一项能力都是插件。**

**关键事实**:
- **2026-08-13** 发布 v0.1 **开发者预览版**,同步以 **MIT 协议开源**。
- 底层基于 **Cordis** 插件内核。
- 模型、工具、技能、会话、沙箱、存储、调度、UI 全部可替换 —— **不需要改源码,挂插件就行**。
  连 Agent 循环本身都能从配置层替换。
- 一个 `cordis.yml` 决定这个 agent 有哪些能力:
  加 LLM 适配器 + 文件系统 + Bash + TUI → 终端编程 agent;
  把界面换成 Web 插件 → 浏览器应用;
  用 Headless 入口 → 别的程序可以驱动的自动化服务。
- **四种运行模式**:标准 / PTC(用模型生成代码组合多轮工具调用)/ 极简(只留 Shell 和文件编辑,用于基准测试)/ 创造(在内存里试验新插件)。
- **追记式会话日志**:系统提示词、思维链、工具调用及结果、子 agent 调度、上下文注入全部写进日志,
  可用 **Trajectory 视图**按来源查看;恢复、分叉、检索、回放都基于同一事件流。
- 启动:`npx @deepseek-ai/dsh web` 一行命令拉起 Web UI。
- 团队 2026-03 成立,明确对标 Anthropic 的 Claude Code。
- 官方明确定位:V4-Flash 的 agent 基准成绩(如 TerminalBench 2.1 得 82.7)就是用它测的。

**命中什么**:**"我不想被某一家厂商锁死,而且我要能看见它每一步在干什么。"**
受众是**会折腾的人**(开发者、企业平台方),不是普通职场人。

**代价/注意**:
- v0.1 是**早期预览版**,官方明确"核心插件与基础接口将持续快速迭代" → API 不稳定,生产引入要锁版本。
- 它和 DeepSeek 的模型是**两回事**:模型是模型,这是运行环境。
- 能力上限还没有正式版和第三方基准验证。

**数字上屏幕**:**MIT**(开源协议)/ 或 **v0.1**(2026-08-13 开发者预览)

## 7. 怎么选(用户点名要的)

### 第一刀:先分两条道(这是选型最常犯的错)

> **把 Trae 和 WorkBuddy 放一个擂台里比,第一步就错了。**

| | 编程 Agent(Coding Agent) | 工作 Agent(Work Agent) |
|---|---|---|
| 核心活 | 写代码、改代码、跑工程 | 写文档、做分析、跑流程、控浏览器 |
| 代表 | Codex、Claude Code、Trae IDE、CodeBuddy | **WorkBuddy**、QoderWork、TRAE Work、豆包工作 |
| 用户 | 开发者 | 全体职场人 |

### 第二刀:编程 Agent 内部

- **习惯终端、要最大控制权** → Claude Code(权限提示最细、生态最深)
- **已经在付 ChatGPT 订阅、要云端并行** → Codex
- **不习惯终端、要看得见** → Trae(个人版免费,中文优先)

### 第三刀:工作 Agent 内部

- **不想折腾、用微信/企微** → WorkBuddy
- **想自己改、不被锁死** → DeepSeek Harness
- **纯海外栈** → Claude Cowork / ChatGPT Work

### 六个共同点(为什么观众会觉得"它们好像差不多")

1. 都不只是聊天框
2. 都支持代理式工作流(给目标,自己拆步骤)
3. 都搞上下文工程
4. 都开放扩展(MCP / Skills / Connector)
5. 都在"云 + 本地"之间找平衡
6. 都在从"个人提效"往"组织生产力"卷

> 这一条对课件很有用:**先承认"它们确实像",再讲"差在哪"**,观众才会服。

### 三个最现实的硬指标(普通人真正会在意的)

1. **门槛**:要不要翻墙、要不要配环境、要不要绑卡
2. **入口**:终端 / 编辑器 / 桌面 / 手机
3. **花钱**:免费额度多少,超了怎么算
