# 抖音 AI 科普课 · 课件工作区

给普通人看的 AI 科普短视频课件。横屏 16:9,自包含 HTML,离线可用。

## 目录

```
contract.md                  ← 课件契约。改课件前先读它
courseware/
  lesson-01.html             ← 第 1 讲:AI 公司和大模型是什么关系
  lesson-02.html             ← 第 2 讲:会自己动手的 AI(五个工具)
  lesson-03.html             ← 第 3 讲:模型这么多,到底该怎么选
  build.ps1                  ← Windows:把 CSS / JS / 图标重新内联进所有 lesson-*.html
  build.sh                   ← macOS / Linux:build.ps1 的等价物(产物一致)
  assets/deck.css            ← 设计系统源文件
  assets/deck.js             ← 放映器源文件
  assets/logos/*.svg         ← 15 个官方品牌图标(内置,不走 CDN)
README.md                    ← 本文件
```

三讲课件都是**自包含单文件**,CSS、JS、图标全部内联。
可以单独复制到任何地方双击打开。`assets/` 是**唯一真源**。

## 第二讲:五个工具,五种形态

**这一讲的主线不是「有哪五个工具」,是「这五个到底差在哪」。**
所以五个工具页**各用一套骨架、各画一种示意图** —— 上一版十个页面版式完全一样,
观众看不出区别,已被判定不可用(见契约 v2.2 的版本记录)。

| 页 | 内容 |
|---|---|
| 1–3 | 封面 → 承接第一讲的三层框架 → **核心区分:聊天框 vs 干活工具** |
| 4 | **为什么是现在**:四段时间线(OpenClaw → 大厂进场 → 成一个真市场) |
| 5–6 | **Codex**(OpenAI)—— 汇聚骨架:一个内核,四套壳 |
| 7–8 | **Claude Code**(Anthropic)—— 左右骨架:环形工作循环 |
| 9–10 | **Trae**(字节跳动)—— 上下骨架:整宽三栏 IDE |
| 11–12 | **WorkBuddy**(腾讯)—— 左右骨架:电脑 ↔ 手机 |
| 13–14 | **DeepSeek Harness**(DeepSeek)—— 上下骨架:插件拼装台 |
| 15 | **怎么选**:先分两条道,再各问一个问题 |
| 16 | 五工具对照表(建议暂停截图) |
| 17 | 收尾:分两条道 → 看入口 → 看门槛 |

每个工具的第二页都有一条 **数据带**(`.statband`),放一个可核实的数字 ——
Codex 的周活增长、Claude Code 的「最受喜爱」比例、Trae 的国内份额、
WorkBuddy 的月访问量、Harness 的版本号。**没有数字的页面视为未完成**。

### 数字与口径

- 屏幕上只放**一个**数字,**口径和出处写在口播备注里**。
- 凡属**厂商自称**的写「官方说」;凡属**第三方调研**的必须说明是调研。
  例:Claude Code 的 46% 来自第三方开发者调研(906 人),不是官方数字;
  WorkBuddy 的 2097 万来自易观报告,腾讯财报只背书了留存率和「使用最广」。
- 底稿与全部出处见 `artifacts/shared/research-lesson02-agents.md`。

### 五张示意图是矢量的,不是图片

第 5/7/9/11/13 页的示意图是**内联 SVG 画出来的**,不是截图。五张的**画法互不相同**:
汇聚、环形、三栏、两端、拼装台。

- 好处:矢量、放多大都清晰、不占体积、没有版权风险、不会过期
- 代价:它不是真实界面截图,是示意

如果你想要**真实截图**,可以在课件里换成图片:把截图放进
`courseware/assets/shots/`,然后在对应页把 `<svg class="diagram">…</svg>`
整段换成 `<img class="diagram" src="assets/shots/xxx.png" alt="…">`,
最后跑一次 `build.sh`(它只内联图标,CSS/JS 之外不会自动内联图片,
所以图片要么保持相对路径,要么你手动换成 data URI)。

## 第三讲:有个活要干,该挑哪个模型

**按真实工作场景分,不按厂商的型号分类。**

核心论断:**大部分人其实不用挑模型** —— 你不是在挑模型,你是在某个 Agent 里干活,
工具默认配好的那个通常就够用。真正要挑的只有两种情况:工具弹出来让你选,
或者你要把 AI 接进自己的工作流。

| 页 | 内容 |
|---|---|
| 1–3 | 封面 → 三讲连起来 → **核心反转:大部分人其实不用挑模型** |
| 4 | 五个真实场景总览 |
| 5 | 场景一 **纯对话、问问题** — GPT-6 Luna / Gemini 3.1 Pro / DeepSeek V4.1 Flash |
| 6 | 场景二 **写东西、改文字** — Claude Sonnet 5.5 / GPT-6.1 Sol / Kimi K3 |
| 7 | 场景三 **做 PPT、做表格** — Kimi K3 / Gemini 3.1 Pro / Doubao-Seed-2.1 |
| 8 | 场景四 **生图、做视频、配音** — Seedream 5.0 Pro / Seedance 2.5 / MiniMax Speech 2.8 |
| 9 | 场景五 **写代码、改代码** — Claude Sonnet 5.5 / GPT-6.1 Sol / MiniMax M3 |
| 10 | **旋钮:「快省」和「准强」是一根轴的两端** |
| 11 | 三个误区 |
| 12 | **把活说清楚:同一件事,两种说法** |
| 13 | 五个场景对照表(建议暂停截图) |
| 14 | 三步流程 —— 注意「挑具体型号」不在前三步 |
| 15 | 收尾 + 下一集预告 |

第 5–9 页版式是左右两栏:左栏是这类场景的**真实说法示例**(3 条,
例如「把这份报告变成 10 页 PPT」),右栏是这类场景该挑的**3 个具体型号**
(带厂商图标),底部一行写**落到哪个工具**。

### 右栏的型号是按「档位」取的,不是按「最贵」

五个场景的右栏一律取**这个活够用的那一档**,不默认推旗舰:

| 场景 | 取哪一档 | 为什么 |
|---|---|---|
| 纯对话 | 轻量档 / 主力档 | 问问题这件事,轻量档就是这个场景的正确答案 |
| 写东西 | 均衡档 / 主力档 | 要的是文笔,不是跑分;同一条产品线的均衡档就够 |
| 做 PPT 表格 | 能落到文件上的那些 | 关键在能不能直接给你一个文件(出 `.pptx` / `.xlsx`,或直接改本地那份),不在谁最强 |
| 生图做视频 | 各家那一支单用途型号 | 一个型号只干一件事,这一类没有「最强」可比 |
| 写代码 | 编程专用档 | 编程榜上主力档本来就在第一梯队,旗舰只在极限任务里才值 |

**第三讲一个旗舰型号都没出现,这是刻意的** —— 五个场景里没有一个是「极限任务」。
要更强,用第 10 页那根旋钮(打开思考模式),不是去买最贵的型号。
复检时先确认这一档还在售、有没有被新版本取代。

### ⚠️ 三个必须保留的东西

1. **「五个场景」是课件自己搭的框架**,不是厂商官方分类,也不是业界标准。
   划法依据是「普通人在电脑前实际会遇到的活」。录制时请在口播里说明
   (第 4 页备注已写)。
2. **「大部分人不用挑模型」有前提**:仅当工具已经自动替你选好模型时成立。
   工具弹出模型选择、或你要接进自己的工作流时,这条不成立。第 3 页已把前提
   写在屏幕上,后续引用不要省掉。
3. **「快省 ↔ 准强」是旋钮,不是场景**。第一版第三讲把「量大要省钱」当成一个
   场景,被判不可用 —— 抽象维度观众对不上号。它现在是第 10 页那根轴。

## 改内容

- **改文案**:直接改 `lesson-0X.html` 里对应的文字。
- **改颜色 / 字号 / 版式**:改 `courseware/assets/deck.css`,然后重新内联:

  ```powershell
  # Windows
  powershell -ExecutionPolicy Bypass -File build.ps1
  ```

  ```bash
  # macOS / Linux(产物与 build.ps1 一致)
  cd courseware && bash build.sh
  ```

- **改图标**:替换 `courseware/assets/logos/<key>.svg` 后同样跑一次 build。
  两个脚本都会自动处理目录下**所有** `lesson-*.html`。

两个脚本都只替换三段内容(CSS、JS、图标占位符),**不动课件正文**,可反复运行。
**忘了跑这一步,你在 assets 里的改动不会生效。**

> ⚠️ `build.ps1` 和 `build.sh` 是**同一套规则的两种实现**。
> 改了其中一个,另一个必须同步改,否则两个平台上的产物会不一致。
>
> ⚠️ `build.sh` 用**原子写**(临时文件 + rename)。`build.ps1` 还是直接覆盖写 ——
> 如果同一时刻有别的进程在写同一个 `lesson-*.html`,文件会被写坏。
> 详见契约 8.5,补丁代码也写在那里。

自检(很土但有效):

```bash
grep -c '</html>' courseware/lesson-*.html   # 每个文件都必须是 1
```

## 出问题时先看这里

| 症状 | 原因 |
|---|---|
| **所有内容按文档流堆在一起、没有分页** | CSS 没生效。文件被改回用 `<link>` 引外部 CSS 了。跑一次 `build.ps1`。 |
| **公司页 / 工具页左右两栏上下堆起来** | 页面级版式被 `.slide.is-active` 的 `display:flex` 压掉了。现在的版式都挂在独立元素上(`.co-main`、`.tool-main`),不要再往 `.slide` 上加 `display`。见契约 8.2。 |
| **图标位置是空白** | `assets/logos/<key>.svg` 缺失,或占位符写法不对(必须是 `<!--LOGO:key--><!--/LOGO-->`)。 |
| **build.ps1 报语法错或输出乱码** | .ps1 丢了 UTF-8 BOM。Windows PowerShell 5.1 会把无 BOM 的脚本按 GBK 解码。见契约 8.3。 |
| **翻了页但控制台报 `replaceState` 错误** | `file://` 下 Chrome 禁止这个 API,已 try/catch 吞掉。若又出现说明 JS 被换回旧版。 |

## 已知事项(不要修,先读)

**内容层面**
- 五家公司的工具覆盖是有结构的:Codex / Claude Code / Trae 是**编程 agent**,
  WorkBuddy 是**办公 agent**,DeepSeek Harness 是**开源的运行环境**。
  三者不是同一类东西,第 3 页把这条线拉出来讲,第 15 页用它做选型的第一刀。
- **腾讯没有出现在第一讲的 9 家公司里**,但第二讲有腾讯的 WorkBuddy。
  如果要保持两讲一致,第一讲可能该补上腾讯(混元)。**这是待你决定的缺口。**
- 型号与产品信息截至 **2026-10**。按契约第 9 条每季度复检一次。
- **第一讲的型号表比市场慢半拍**:第一讲列的是 `GPT-6 Sol`(主力 / 2026-10),
  但 OpenAI 已于 **2026-09-29** 发布 `GPT-6.1 Sol`(官方口径:接近 Astra、约五分之一价格),
  第三讲用的是 GPT-6.1 Sol。Google 那边也一样:第一讲只列了 Argon / 3.1 Pro / Gemma,
  没列 Flash 档。**下次复检时先补第一讲的表**,否则两讲的型号对不上。
- **第二讲的数字都会过期,而且过期得比型号快。** 2097 万、41.2%、500 万周活
  这类数字建议**每季度重查一次**;重查时改 `.statband .s-num` 和口播备注两处。

**技术层面**
- ⚠️ **2026-10-20 课件被写坏过一次**:`lesson-03.html` 尾部出现重复的 `</html>` 碎片,
  原因是 build 直接覆盖写、和另一个进程的写入交错。已截断修复,`build.sh` 改成原子写。
  契约 8.5 记了档。**每次改完课件,顺手数一下 `</html>` 的个数。**
- ⚠️ **v2.2 修掉了一个会毁掉录制的 bug**:`deck.css` 里原本没有 `.notes` 规则,
  于是每一页的**口播备注都被渲染在幻灯片底部**(深色 16px,被 `#stage` 裁成一行)。
  现在 `.notes{display:none}` 已加上。**改 deck.css 时不要删掉这条。** 见契约 8.4。
- **brand 色值已全部核实**,取自 simple-icons 官方库或公司官网 logo 本身:
  其中 WorkBuddy 的 `#0EC8A9` 是从它官方 logo 的渐变里取的。
  ⚠️ Trae `#32F08C` 和 WorkBuddy `#0EC8A9` 都是绿色系 —— 靠**骨架不同**区分,别改色。
- **xAI 与月之暗面的官方品牌色都是纯黑**,图标底看起来一样 —— 这是事实。
- **Codex 用的是 OpenAI 的标记**,因为在官方图标库里 Codex 没有独立图形。
- **WorkBuddy 的图标**是从官网 logo 里提取的白色字形(SVG 里形状本身溢出视口、
  靠 viewport 裁切,与官方原图行为一致)。
- **布局做过几何实测(2026-10-20)**:用 headless Chrome 在 1920×1080 下逐页量过 ——
  17 页全部无溢出、无横向越界、右下角死区(`x > 1670 且 y > 930`)内无文字。
  截图留在 `artifacts/shared/shots/p01..p17.png`。
  ⚠️ 这是**几何**核对,**不是视觉核对**:观感(配色、疏密、重心)仍需人眼看。
  改动版式后请重跑一次,别只靠算式。
